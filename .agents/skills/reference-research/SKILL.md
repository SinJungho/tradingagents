# 레퍼런스 조사

## 1. 범위 정하기

비교할 질문을 먼저 한 문장으로 고정한다(예: "종목별 다중 관점 분석의 역할 체계", "Trader·Risk 결정 단계 구조"). 질문과 무관한 기능 나열은 하지 않는다.

## 2. 조사

- 저장소 원본을 읽는다: README보다 실제 에이전트 정의, 그래프 연결, 신호 스키마, 백테스트 코드. 커밋 해시나 날짜를 남긴다.
- 성과 주장은 원 논문·원 저장소의 수치와 기간을 확인하고, 기간이 짧거나 미래 정보 유입 위험이 있으면 그렇게 표시한다.
- 확인하지 못한 주장은 "미확인"으로 둔다. 출처 URL을 모두 남긴다.
- 독립 조사자가 필요하면(사용자가 Claude/Codex worker를 요청한 경우) Orca orchestration으로 조사 전용 worker를 띄우고, 저장소 수정 금지·결과는 `worker_done` 본문으로 받도록 지시한다. worker 결과는 그대로 채택하지 않고 저장소 코드와 대조해 틀린 부분을 표시한다.

## 3. 비교와 추천

| 후보 | 핵심 구조 | 이 저장소 그래프에 넣을 위치(파일·노드) | 재현성·백테스트 적합성 | 비용 | 위험 |

- 기존 TradingAgents 흐름(analyst → Bull/Bear → Research Manager → Trader → Risk → Portfolio Manager)과의 접점을 구체적인 파일 이름으로 쓴다.
- 1안·차선안·비추천안과 이유를 쓴다. 실존 인물 페르소나처럼 근거 추적이 어려운 방식은 위험을 명시한다.
- 채택하면 다음 단계는 `openspec-change` skill로 넘긴다. 코드보다 먼저 결정론적 기준선과 평가 방법을 정한다.
