# 일봉 수집과 장기·최근 추세선

이 절차는 사용자가 요청한 종목에 적용한다. Python 계산 결과에는 분석 기간·거래소·가격 기준을 기록한다. `chart-zones` v1의 ZigZag, 구간 통계와 별도인 전후 5봉 분석이다.

## 1. 수집 및 확인

1. `open_chart`로 요청 종목을 열고 `get_drawing_guide`와 `read_drawings`를 먼저 확인한다. `set_periodicity(interval=1, timeUnit="day")` 뒤 `get_chart_summary`에서 종목, 일봉, 최신 완료 거래일을 확인한다. 사용자가 기준일을 주면 그 날짜 이하의 최신 완료 거래일을 쓴다.
2. 완료 거래일을 끝으로 달력상 5년 전부터 `set_range(start, end)`를 요청한다. `get_chart_summary`의 `loaded_range`와 `total_bars_loaded`로 전체 일봉 범위가 확인되면 그대로 내보낸다.
3. 주봉으로 전환되거나 전체 범위를 확인할 수 없으면 1년 단위 날짜 구간으로 나눈다. 구간마다 `set_range` → `set_periodicity(interval=1, timeUnit="day")` → `get_chart_summary` 순서로 호출한다. 구간 요청값, 확인된 `loaded_range`, `total_bars_loaded`, 실제 반환 범위와 행 수를 기록한다. 이전 데이터셋이 남거나 앞뒤 경계가 누락되면 범위를 넓힌 뒤 일봉을 다시 지정하고 빠진 날짜만 재조회한다.
4. 각 구간은 `get_chart_data(from, to)`로 받는다. `last_n`을 생략해 기본 50봉 조회 경로를 피하고, `max_points`도 생략해 봉을 합치거나 축약하지 않는다. 요청 경계는 실제 반환 타임스탬프 형식에 맞춘다. 결과가 `bucketed`이면 그대로 사용하지 않는다. 실제 첫·마지막 봉과 행 수를 확인한다.
5. 원문 CSV 블록을 보존한다. Python에서 확인된 타임스탬프 기준으로 대상 거래소의 거래일을 대응시키고 날짜 기준으로 정렬·중복 제거한다. 동일 날짜의 OHLCV가 다르면 값을 섞지 말고 가격 조정·거래량 기준과 원본 응답을 재확인한다. 종목 거래소의 거래일 달력과 대조해 합친 시작·끝 날짜, 고유 봉 수, 누락·추가 거래일, 중복 수를 기록한다. OHLC 순서와 거래량 결측을 검사한다. 전체 일봉을 다시 받을 수 있으면 병합본과 대조한다.
6. 드로잉에 앞서 거래일·OHLCV 검증을 통과시킨다. TradingAgents의 `chart-check`로 Yahoo 가격도 대조할 때는 [원문 블록 검증 절차](operations.md#2-tratto-차트-준비-및-검증)를 적용하고 결과를 별도로 기록한다. 검증에 실패한 구간은 누락과 이유를 보고하고 그 결과로는 드로잉하지 않는다.

- 사용자가 5년보다 길거나 최소 봉 수를 지정하면 그 범위를 우선한다. 2,500개 일봉은 미국 시장에서 약 10년이다. 내보낸 전체 봉 수와 실제 화면의 첫·마지막 거래일 및 봉 수를 따로 확인한다.
- Yahoo가 장기 보기를 주봉으로 바꾸거나 범위를 줄이면 일봉을 유지하는 보기로 다시 설정하고 `get_chart_summary`로 주기·로드 수를 확인한다. 한 화면에서 최신 봉이 잘리면 실제 탭의 표시 배율과 오른쪽 여백을 조정한다. 라벨이 작으면 최근 확대 캡처를 추가하고 요청한 장기 보기로 돌아간다.

## 2. Python 분석

- 전후 5봉을 포함한 11봉에서 유일한 최고 고가·최저 저가를 피벗으로 잡는다. 양쪽 5봉이 없는 끝부분은 확정 피벗에서 제외한다. 피벗 날짜와 원본 고가·저가를 보존한다.
- ATR(14)은 첫 14개 True Range의 평균으로 시작하고 Wilder 방식으로 갱신한다. 피벗 반응은 이후 봉의 반대 방향 최대 이동을 피벗 시점 ATR로 나눈다. 직전 20봉 평균 거래량 대비 피벗 봉의 거래량 배수도 기록한다. 앞선 NVDA 분석의 기본값은 반응 관찰 15봉, 최소 반응 1 ATR, 독립 터치 간격 10봉이다. 사용 가능한 관찰 봉이 짧거나 ATR·거래량 기준이 아직 없으면 표시한다.
- 날짜보다 가격이 가까운 피벗부터 군집화하고, 가격 대비 폭과 ATR을 기준으로 너무 넓게 묶이지 않게 제한한다. 앞선 분석에서는 군집 최저가를 P, 군집의 최저가 피벗과 새 후보 피벗의 ATR 중 작은 값을 A로 두고 최대 폭을 `max(0.025 × P, min(0.05 × P, 0.75 × A))`로 정했다. 사용한 기준을 기록한다. 독립 반응이 두 번 이상인 구간만 후보로 남긴다. 각 구간의 상·하단, 터치 날짜·횟수, 종가가 상단을 넘거나 하단을 밑돈 날짜와 종가를 저장한다. 최종 종가 기준으로 지지·저항·현재가 포함 구간을 구분한다.
- 장기는 5년 전체, 최근 추세는 마지막 1년에서 각각 피벗 쌍을 찾는다. 상승선은 실제 피벗 저점 두 곳, 하락선은 실제 피벗 고점 두 곳을 사용한다. 간격, 반응 ATR, 상대 거래량, 두 점 사이 침범 및 이후 종가 이탈을 비교해 날짜·가격과 선정 근거를 기록한다. 조건에 맞는 쌍이 없으면 해당 선을 생략한다.
- 두 피벗을 잇고 마지막 완료 봉까지의 연장 좌표는 일봉 순번 간격과 동일한 기울기로 계산한다. 가격이 이미 이탈한 선은 상태를 명시한다.

### 당일 흐름에 맞는 장기 상승선

장기 마지노선과 최근 사이클 선을 따로 비교한다. 마지노선을 보존하라는 요청이 있으면 그 선을 비교 기준으로 두고, 교체할 선은 종류·날짜·가격과 스타일로 특정한다.

```bash
tradingagents chart-trendlines --symbol QQQ --chart-csv path/to/merged-tratto.csv \
  --start 2016-10-03 --as-of 2026-11-20 --pivot-start 2022-10-01 \
  --min-bars 2500 --chart-timezone Asia/Seoul \
  --compare-anchor 2020-03-23 --extend-to 2026-12-07 --json
```

- 예시 날짜·종목·봉 수는 요청에 맞게 바꾼다. `--start`와 `--as-of`는 분석 범위의 첫·마지막 완료 거래일이며, `--pivot-start`는 비교를 시작할 사이클 날짜다. 기준일 이후 봉은 분석에 들어가지 않는다.
- `counts`의 저점 쌍·기울기/기간·종가 근접·과거 이탈·최종 통과 수를 구분해 답한다. `candidates`의 순위와 독립 반응을 근거로 선정 이유를 설명한다. 마지막 정규장 종가와 시각이 확인된 장외 시세를 구분한다. 이탈한 선은 회복 관찰 기준으로 표시한다. 최종 후보가 없으면 그 조건과 이유를 보고한다.
- 후보 선을 “최적” 또는 “완벽”이라고 단정하지 않는다. 조건별 후보 수, 선정한 앵커, 독립 반응, 과거 이탈, 현재 종가와의 거리, 같은 출발점 대안의 결과를 보고하고 예측력은 별도로 검증됐는지 표시한다.
- `--compare-anchor`로 마지노선 시작 저점을 지정하면, 같은 출발점에서 선정 선의 기준일 높이까지 그은 대안의 종가 하회 횟수와 첫 날짜를 비교한다. 이 대안의 실제 표시는 사용자가 요청한 경우에 한다. 계산과 화면의 로그 축을 맞춘다.
- “오늘부터 2주”는 시장 현지 날짜의 달력상 14일이다. 종료일이 휴장일이면 그날까지의 마지막 거래일을 쓰고 두 날짜를 밝힌다. `--extend-to`는 동일 기울기로 계산한 실제 거래일 좌표를 반환한다. 스타일은 사용자 지정이 우선이다. 미래 연장값은 차트 좌표로 보고한다.
- 결과 JSON을 `data_validation.source: daily-ohlcv` 근거로 보존한다. 반응은 표본 안에서 비교한 결과이며 예측력은 별도다.

## 3. 표시 및 확인

표시를 요청받고 거래일·OHLCV 검증을 통과한 경우 적용한다. 분석만 요청받으면 OHLCV 범위·봉 수, 피벗 방법, 구간의 터치·이탈 이력과 추세선 앵커·선정 근거를 보고한다.

1. 그리기 직전 `get_chart_summary`와 `read_drawings`에서 실제 대상 탭의 종목·일봉·기존 항목을 다시 확인한다. 같은 종류와 날짜·가격 좌표의 객체는 재사용한다. 앵커가 로딩 범위 밖이면 `set_range`와 일봉을 다시 지정하고 실제 로딩을 확인한다.
2. `get_drawing_guide`의 색·두께·개수 기준에 맞춰 주요 가격대만 `draw_rectangle`으로 표시한다. 필요한 단일 가격은 `draw_support`를 쓴다. 추세는 `draw_trendline`으로 표시하고, 마지막 완료 봉까지의 연장선이 필요하면 같은 기울기의 선분으로 잇는다. 보조 도구는 [선택 기준](operations.md#4-보조-도구-선택)을 따른다.
3. 마지막에 `read_drawings`로 ID 또는 fingerprint, 스냅된 날짜·가격을 계산 결과와 대조한다. 화면에서 URL과 종목, 구간, 두 추세선, 배치가 맞는지 확인한다. 동일 종목 탭이 여러 개면 실제 사용자가 볼 탭을 검증한다. 확대·축소로 앵커를 화면 안에 넣고, 필요하면 장기와 최근 화면을 따로 확인한다.
4. [완료 검증과 보고](operations.md#5-완료-검증과-보고)에 따라 실제 사용자 탭을 다시 열어 표시를 확인하고 캡처와 `drawings.json`을 남긴다. OHLCV 검증, 드로잉 확인, 통계적 예측력의 결과를 각각 보고한다.
