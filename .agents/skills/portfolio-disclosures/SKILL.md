# 공개 포트폴리오 공시

결정론적 스크립트 하나로 공식 자료를 읽는다. 13F는 SEC EDGAR, 하원 연간 재무공시와 PTR은 하원 Clerk에서 가져온다. 13F 원문에는 티커가 없으므로 화면에 보이는 행만 CUSIP으로 OpenFIGI(2차 출처)에서 티커를 찾는다. 숫자 계산(합산·비중·분기 비교)은 스크립트가 하고, 에이전트는 결과를 옮기고 한계를 짚는다. 매수·매도 추천이나 현재 보유 단정으로 바꾸지 않는다.

## 1. 대상 정하기

- 대상이 없거나 "유명한 투자자"처럼 막연하면 임의로 고르지 말고 `--list`를 실행해 출력 전체를 ` ```text ` 블록으로 보여 준다. 같은 응답에서 선택창(Claude Code의 `AskUserQuestion`)을 띄워 고르게 한다. 질문 4개를 모두 `multiSelect`로 하고 보기는 아래 고정 목록을 쓴다. 보기에 없는 대상은 "Other"에 목록 번호나 이름을 적게 하고, 질문 문구에 그렇게 안내한다.

  | 질문(header) | 보기(label · description) |
  | --- | --- |
  | 가치투자 | 워런 버핏 · #1 Berkshire Hathaway / 세스 클라만 · #6 Baupost / 리루 · #14 Himalaya / 하워드 막스 · #25 Oaktree |
  | 헤지펀드 | 빌 애크먼 · #2 Pershing Square / 레이 달리오 · #3 Bridgewater / 스탠리 드러켄밀러 · #4 Duquesne / 조지 소로스 · #9 Soros |
  | 기관 | BlackRock · #33 / State Street · #34 / JPMorgan Chase · #35 / 스위스 중앙은행 · #36 |
  | 하원의원 | Nancy Pelosi · CA11 / Josh Gottheimer · NJ05 / Rohit Khanna · CA17 / Marjorie Taylor Greene · GA14 |

  답을 받으면 13F 번호는 `--list`의 CIK로, 하원은 "이름 성"으로 바꿔 한 번에 실행한다. 아무것도 고르지 않으면 실행하지 않는다. 하원 목록은 유명도가 아니라 최근 3년 PTR 건수 상위이므로 목록에 없는 의원도 이름으로 지정할 수 있다. 선택창이 없는 환경(Codex)이나 사용자가 선택창을 거절한 경우에는 목록만 보여 주고 번호를 답하게 한다. 보기 목록은 `disclosures.py`의 `FAMOUS` 순서와 맞춘다. `FAMOUS`를 바꾸면 번호도 고친다.
- 13F는 운용사 이름이나 CIK로 지정한다. 인물은 운용사로 바꿔 넣는다(예: Buffett → Berkshire Hathaway, Ackman → Pershing Square, Dalio → Bridgewater Associates, Druckenmiller → Duquesne Family Office). 이름 검색은 최근 400일 안에 13F-HR을 낸 제출자만 찾는다.
- 하원의원은 성 또는 "이름 성"으로 지정한다. 이름 검색은 최근 3년 하원 색인(PTR·연간 재무공시 제출자) 안에서만 한다.
- 결과 첫 줄의 이름·CIK·지역구가 사용자가 뜻한 대상인지 확인한다. "식별 모호"면 후보를 보여 주고 고르게 한 뒤 CIK나 "이름 성"으로 다시 실행한다.
- 상원의원은 다루지 않는다. 상원의원을 물으면 이 skill의 범위 밖이라고 알린다.

## 2. 실행

저장소 루트에서 다른 명령과 묶지 않은 단독 명령으로 실행한다. 패키지를 불러오며 `.env`의 `SEC_EDGAR_USER_AGENT`가 적용된다.

```bash
.venv/bin/python .agents/skills/portfolio-disclosures/scripts/disclosures.py \
  --filer 1067983 "bridgewater associates" --house Pelosi "Josh Gottheimer"
```

- `--list`: 13F 투자자 표(번호·인물·운용사·CIK)와 기관 표(번호·기관·CIK), 하원 PTR 건수 상위 15명. 조회는 하지 않는다. 13F 목록은 2026-11-19에 SEC에서 CIK와 최근 1년 13F-HR 제출을 확인한 운용사만 담는다.
- `--top N`: 대상별 표시 행 수(기본 10). `--ptrs N`: 의원별로 읽을 최근 PTR 수(기본 5).
- 대상 하나에 몇 초 걸린다(JPMorgan 8,000여 종목도 약 5초). 필요한 호스트는 `www.sec.gov`, `data.sec.gov`, `efts.sec.gov`, `disclosures-clerk.house.gov`, `api.openfigi.com`이다. Codex 샌드박스에는 외부 네트워크가 없으므로 코디네이터나 Claude 세션에서 실행한다.

## 3. 보여 주기(TUI)

스크립트 출력은 78칸 고정폭이며 한글 2칸 폭을 계산해 열을 맞춘다. 대상 요약, 13F 상위 보유, 하원 주식 보유, 하원 거래는 ASCII 테두리(`+`, `-`, `|`) 표로 나온다. 13F 상위 보유 표 아래에는 신규·미보고를 구분·종목·가치·기준(이번 분기/직전 분기) 표 하나로 보이며, 구분별 5행 뒤는 `외 N개`로 줄인다. 13F는 CUSIP의 티커가 하나로 확인된 행만 `브룩필드 코퍼레이션 (BN)`이나 `RESTAURANT BRANDS INTL INC (QSR)`처럼 쓰고, 티커가 없거나 여러 개이거나 조회에 실패하면 원문명을 유지한다(조회 실패는 상세에 한 줄로 표시). 하원 표는 원문 티커를 `구글 (GOOGL)`처럼 한국어 이름과 함께 표시하고, 한국어 이름이 등록되지 않은 티커는 원문 영문명을 줄여 `Clean Energy Fuels Corp. (CLNE)`처럼 쓴다. 칸이 좁으면 이름을 줄이고 티커는 남긴다. 사용자에게는 출력 전체를 ` ```text ` 코드 블록에 그대로 옮긴다. Markdown 표로 다시 쓰지 않는다. 넓은 표는 좁은 터미널에서 줄이 꺾이고, TUI마다 표 렌더링이 다르다.

코드 블록 아래에는 세 줄 이내로만 덧붙인다.

1. 기준일: 13F 보고기간 말과 제출일, 하원 연간 재무공시 신고연도와 제출일, 최근 PTR 제출일. 조회 시각과 구분한다.
2. 빈칸: 식별 모호, 판독 불가, 조회 실패, 비교 불가를 그대로 전한다. 0이나 무보유로 바꾸지 않는다.
3. 사용자가 물은 것에 대한 사실 한 줄. 예: "직전 분기보다 신고 주식 수가 줄어든 종목 6개".

## 4. 해석 한계

- 13F는 분기말 보유이며 분기 후 45일 안에 제출된다. 13(f) 증권만 담고 공매도·현금·비상장·해외 주식은 빠진다. 옵션 행의 가치는 기초자산 기준이다. 수정 신고는 RESTATEMENT면 전체를 대체하고 NEW HOLDINGS면 행을 더한 결과다. "기밀 처리" 표시가 있으면 일부 보유가 빠져 있다.
- 주식 수 변화는 신고된 수량끼리 비교한 것이다. 분할은 증가로, CUSIP 변경(합병·재편)은 신규와 미보고 한 쌍으로 보인다. 실제 매매로 단정하지 않는다. 티커는 13F에 없으므로 OpenFIGI CUSIP 매핑(2차 출처, 공식 아님)으로 붙이며, 해외 CUSIP처럼 미확인 종목은 발행사명을 그대로 쓴다.
- PTR은 거래 신고이며 보유 전체가 아니다. 금액은 신고 구간이므로 중간값, 주식 수, 현재 평가액으로 바꾸지 않는다. 소유(본인·배우자·공동·자녀)는 표시된 그대로 전한다. 스캔으로 낸 PTR은 글자가 없어 "판독 불가"가 되며, 원문 링크를 보고 직접 확인해야 한다. 옵션 행사가·만기는 원문 설명 칸에 있다.
- 하원 주식 보유는 연간 재무공시(Schedule A)의 `[ST]` 유형만 표시하며, 신고연도 말 기준이고 다음 해 5월에 제출된다. 부동산·사업 지분 등 다른 자산 유형은 제외한다. 평가액은 구간이라 비중·합계·중간값을 계산하지 않고, 구간 하한 순으로만 나열한다(같은 구간 안의 순서는 원문 순서). 상한 없는 구간(예: "Spouse/DC Over $1,000,000" → >$1M)이 있다. 같은 연도 수정 신고는 반영하지 않고 건수만 표시한다.
