# 데이터 출처 점검

구현 전에 출처가 실제로 쓸 수 있는지 확인한다. 유료 자료와 접근 제한 우회는 범위 밖이다.

## 1. 점검 항목

공개 URL에 GET 요청을 보내 다음만 확인한다. 응답 원문은 파일로 저장하거나 길게 출력하지 않는다.

| 항목 | 확인 내용 |
| --- | --- |
| HTTP 상태와 형식 | 상태 코드, content-type, 실제 본문 형식. 200이어도 CSV·JSON 대신 HTML 페이지가 올 수 있다(예: iShares 보유 종목) |
| 기준일·시각 | 자료에 기준일(예: "As of 11-Nov-2026")이나 발표 시각이 들어 있는지, 시간대 표기 |
| 규모와 한도 | 행 수, 페이지 크기, 최대 행·offset 한도(예: Yahoo 스크리너 10,000행), 연도별 URL 여부(예: Census 연도별 일정) |
| 식별 요구 | User-Agent에 연락처가 필요한지(예: SEC·BLS는 이메일 없으면 403). 저장소 기존 방식(`sec_edgar._user_agent()`, `SEC_EDGAR_USER_AGENT`)을 따른다 |
| 안정성 | 같은 요청을 시간을 두고 다시 했을 때 같은지, 요청 제한(429·지연)이 있는지 |
| 대체 출처 | 막히면 같은 성격의 무료 공식·준공식 출처(ETF 보유 종목, 기관 일정, FRED 등)를 2~3개 더 본다 |

## 2. 원칙

- 브라우저 위장, 쿠키 탈취, 비공개 엔드포인트 사용 같은 접근 제한 우회는 하지 않는다. 연락처를 밝히는 User-Agent는 우회가 아니라 공급자 요구다.
- 확인하지 못한 내용은 "확인 불가"로 적는다. 관행상 시각(예: "보통 8:30")을 근거 없이 코드에 넣지 않는다.
- 공식 출처가 아니면 출처 종류(공식 / 2차 / 대용치)를 구분해 둔다. 대용치는 보고서·출력에 "공식 아님"을 밝히는 요구사항으로 이어진다.
- Codex 워커의 외부 네트워크는 프로젝트 신뢰·프록시·관리형 정책에 따라 달라진다. 해당 워커의 일반 명령에서 확인하고 결과(상태·형식·형식 표본)를 spec에 넣는다. 승인된 권한 상승 결과는 일반 샌드박스 결과와 별도로 기록한다.

## 3. 기록

결과는 해당 OpenSpec 변경안의 `proposal.md` Why나 `README.md`에 표로 남긴다.

| 출처 | URL | HTTP 상태 | 형식 | 기준일·시각 | 한도·요구 | 판정 |

판정은 "사용", "대용치로 사용(공식 아님 표시)", "사용 불가(사유)" 중 하나다. 사용 불가 출처는 `openspec/NEXT_STEPS.md`에 재확인 대상으로 남긴다.

## 4. 다음 단계

사용할 출처가 정해지면 `openspec-change` skill로 구현한다. 테스트는 확인한 형식 표본을 본뜬 합성 자료로 쓰고, 구현 뒤 실제 출처로 한 번 다시 확인한다.
