# api-network-resilience Specification

## Purpose
TradingAgents가 데이터 API 네트워크 실패를 안전하게 진단하고 제한적으로 재시도한다.

## Requirements

### Requirement: 외부 데이터 호스트 도달성 진단

시스템 MUST 현재 프로세스에서 공개 데이터 API 호스트의 DNS·HTTP(S) 도달성을 인증정보 없이 확인하고 결과를 제공자별로 표시해야 한다. 사용자 지정 endpoint의 전체 URL, 인증정보, 요청 헤더, 응답 본문은 출력하지 않아야 한다.

#### Scenario: 호스트에 도달 가능

- **WHEN** DNS 조회가 성공하고 인증 없는 HTTP(S) 요청에서 응답을 받을 때
- **THEN** 시스템은 해당 호스트에 도달 가능하다고 표시하고 응답 본문을 읽거나 출력하지 않는다

#### Scenario: 네트워크 계층별 실패

- **WHEN** DNS, 연결, 시간 초과 또는 TLS 단계에서 요청이 실패할 때
- **THEN** 시스템은 실패 범주를 분리해 표시하고 원시 예외 메시지는 출력하지 않는다

### Requirement: 멱등 GET의 제한 재시도

시스템 MUST 외부 데이터 GET 요청에서 DNS·연결·시간 초과·제공자 서버 오류만 제한된 횟수로 지수 백오프 재시도해야 한다. 인증, 권한, 요청 제한, 계정 한도 및 TLS 인증서 오류는 자동 재시도하지 않아야 한다.

#### Scenario: 일시적 전송 실패

- **WHEN** 멱등 GET이 재시도 가능한 오류를 반환하고 시도 횟수가 남아 있을 때
- **THEN** 시스템은 제한된 지수 백오프 후 재요청하고 제공자·호스트·오류 범주·시도 수만 기록한다

#### Scenario: 영구 또는 인증 오류

- **WHEN** GET이 인증·권한·요청 제한·한도·TLS 오류를 반환할 때
- **THEN** 시스템은 같은 요청을 재실행하지 않는다

#### Scenario: 모든 재시도가 실패

- **WHEN** 재시도 가능한 오류가 허용 횟수만큼 지속될 때
- **THEN** 시스템은 마지막 오류 범주를 유지하며 API 키, URL의 비밀 쿼리, 원시 응답 또는 예외 원문을 기록하지 않는다
