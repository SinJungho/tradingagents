# stock-discovery Specification

## Purpose
사용자가 제공한 최대 10개 미국 개별 주식의 현재 결정론적 팩터 신호와 데이터 공백을 표시한다.

## Requirements

### Requirement: 사용자 지정 티커 목록 입력과 검증

시스템 MUST 사용자가 명시한 서로 다른 미국 개별 주식 티커 목록만 받아야 하며, 목록은 비어 있지 않고 최대 10개여야 한다. CLI MUST `tradingagents discover --tickers NVDA,AAPL` 형식을 제공하고, Python API MUST 호출 가능한 `discover_stocks(tickers)` 진입점을 제공해야 한다. 시스템 MUST 목록 수, 티커 형식 및 중복 여부를 모든 공급자 호출 전에 검증해야 하며, 잘못된 입력은 공급자 호출 없이 거부해야 한다.

#### Scenario: 유효한 한정 목록

- **WHEN** 사용자가 형식에 맞는 서로 다른 티커를 1개 이상 10개 이하로 제공할 때
- **THEN** 시스템은 입력 순서를 보존한 채 각 티커의 현재 결정론적 팩터 점수를 계산한다

#### Scenario: 빈 목록, 중복 또는 10개 초과 목록

- **WHEN** 사용자가 빈 목록, 중복 티커, 잘못된 티커 또는 10개보다 많은 티커를 제공할 때
- **THEN** 시스템은 공급자를 호출하지 않고 입력 오류를 반환한다

### Requirement: 기존 결정론적 팩터 점수 사용

시스템 MUST 기존 `value`, `growth`, `quality`, `momentum` 스타일 점수 계산과 그 고정 기준값을 현재 데이터에 사용해야 한다. 시스템 MUST 종목 간 입력 순서를 보존하고 티커별 팩터 신호를 반환해야 하며, 합성 점수·교차 종목 순위·새 임계값·투자 추천을 생성해서는 안 된다. 이 기능은 LLM을 호출하거나 후속 분석을 실행해서는 안 된다.

#### Scenario: 점수가 있는 현재 자료

- **WHEN** 한 티커의 기존 점수 계산에 필요한 자료가 제공될 때
- **THEN** 시스템은 각 팩터의 기존 신호와 기존 점수를 반환하고 입력 순서를 유지한다

#### Scenario: 일부 팩터 입력 누락

- **WHEN** 한 티커의 하나 이상의 팩터 계산에 필요한 입력이 없거나 유효하지 않을 때
- **THEN** 시스템은 해당 팩터를 기존 `ABSTAIN` 상태와 누락 입력으로 표시하고 다른 계산 가능한 팩터는 반환한다

### Requirement: 출처, 날짜, 부분 결과 및 실행 건수 공개

시스템 MUST 결과에 사용한 데이터 출처, 사용 가능한 각 팩터 지표와 그 기준 날짜, 누락 입력, 티커별 공급자 실패 및 요청·시도·반환 티커 수를 표시해야 한다. 요청 수는 검증된 입력 티커 수, 시도 수는 점수 계산을 시작한 티커 수, 반환 수는 일부 또는 전체 팩터 결과 레코드를 받은 티커 수로 정의한다. 시스템 MUST 누락 날짜를 알 수 없음으로 표현하고, 입력 목록 밖의 종목을 탐색했거나 시장 전체를 다뤘다고 주장해서는 안 된다.

#### Scenario: 일부 팩터만 계산 가능

- **WHEN** 한 티커의 일부 팩터는 점수화되지만 다른 팩터는 `ABSTAIN`일 때
- **THEN** 시스템은 계산된 팩터의 출처와 기준 날짜, 누락 입력 및 전체 실행 건수를 표시하고 해당 티커를 부분 결과로 반환한다

#### Scenario: 한 티커의 공급자 실패

- **WHEN** 공급자 오류로 한 티커의 팩터 계산이 실패할 때
- **THEN** 시스템은 해당 티커 오류를 결과에 기록하고 나머지 입력 티커는 계속 처리한다

#### Scenario: 공급자가 기준 날짜를 제공하지 않음

- **WHEN** 사용 가능한 지표에 기준 날짜가 없을 때
- **THEN** 시스템은 날짜를 알 수 없음으로 표시하고 현재 기준 자료라고 단정하지 않는다

### Requirement: Nasdaq-100 유니버스 탐색

시스템 MUST `tradingagents discover --universe nasdaq100`을 지원하고, `--tickers` 목록과 `--universe`는 한 번에 하나만 허용해야 한다. 시스템 MUST 자동으로 갱신 가능한 공개 Nasdaq-100 종목 목록에서 티커와 그 출처가 선언한 구성 기준일을 읽어야 하며, 목록을 코드에 고정하거나 가져오기 실패 시 임의 또는 이전 목록으로 대체해서는 안 된다. 결과 MUST 유니버스 출처 URL, 구성 기준일, 점수 데이터 기준일, 요청·시도·반환 수를 표시해야 하며, 해당 출처에서 확인한 Nasdaq-100 종목 범위만 다뤘다고 밝혀야 한다.

#### Scenario: 공개 목록을 읽고 점수 계산

- **WHEN** 사용자가 `--universe nasdaq100`을 선택하고 공개 목록에 명시된 기준일과 티커 표를 읽을 수 있을 때
- **THEN** 시스템은 표의 각 티커를 입력 순서대로 기존 결정론적 네 스타일 점수기로 평가하고 출처 URL과 구성 기준일을 표시한다

#### Scenario: 유니버스 출처를 읽을 수 없거나 형식이 바뀜

- **WHEN** 공개 목록 요청에 실패하거나 기준일·완전한 티커 목록을 검증할 수 없을 때
- **THEN** 시스템은 한 줄 오류를 반환하고 티커를 임의로 만들거나 저장된 임의의 목록을 대신 평가하지 않는다

#### Scenario: 명시 목록과 유니버스가 함께 제공됨

- **WHEN** 사용자가 `--tickers`와 `--universe`를 동시에 제공하거나 둘 다 생략할 때
- **THEN** 시스템은 데이터 공급자를 호출하지 않고 사용법 오류를 반환한다

### Requirement: 기존 지정 티커 탐색 유지

시스템 MUST `--tickers`와 `discover_stocks(tickers)`의 기존 최대 10개 입력 검증, 입력 순서, 부분 실패와 출력 동작을 보존해야 한다. Nasdaq-100 유니버스 경로 MUST 기존 네 스타일의 신호와 고정 기준값만 사용하고, 합성 점수·종목 간 순위·추천·LLM 후속 분석을 만들지 않아야 한다.

#### Scenario: 기존 명시 목록 호출

- **WHEN** 사용자가 `tradingagents discover --tickers NVDA,AAPL`을 호출할 때
- **THEN** 시스템은 이전과 같이 해당 목록만 평가하고 입력 순서를 유지한다

#### Scenario: 구성 종목별 자료 공백 또는 제공자 실패

- **WHEN** 구성 종목의 입력 자료가 없거나 그 종목의 제공자 호출이 실패할 때
- **THEN** 시스템은 기존 `ABSTAIN`과 종목별 실패를 표시하고 나머지 종목을 계속 평가한다
