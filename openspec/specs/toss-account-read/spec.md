# toss-account-read Specification

## Purpose
토스증권 공식 API에서 사용자가 선택한 계좌 정보를 조회하되, 인증과 업무 요청을 읽기 전용 경계 안에 둔다.

## Requirements

### Requirement: 공식 호스트와 조회 경로만 호출

시스템 MUST 토스증권 공식 OpenAPI 호스트에서 승인된 경로의 조회 `GET`만 업무 요청으로 호출해야 한다. OAuth 토큰 발급은 인증 모듈 안의 정확한 토큰 경로에 대한 `POST`만 허용해야 한다. 메서드·호스트·경로를 함께 검사하고 리다이렉트를 따라가지 않아야 한다.

#### Scenario: 조회 요청 허용

- **WHEN** 어댑터가 계좌·보유·주문 조회를 요청할 때
- **THEN** 검증된 호스트와 allowlist 경로의 `GET` 요청만 전송한다

#### Scenario: 주문 요청 차단

- **WHEN** 주문 생성·정정·취소 또는 조건주문 경로를 요청할 때
- **THEN** 네트워크 전송 전에 거부하고 요청 본문이나 인증정보를 로그에 남기지 않는다

#### Scenario: 임의 호스트와 리다이렉트 차단

- **WHEN** 허용되지 않은 호스트·경로를 사용하거나 응답이 리다이렉트를 반환할 때
- **THEN** 후속 요청을 보내지 않고 실패로 표시한다

### Requirement: 계좌를 명시적으로 선택

시스템 MUST 계좌 목록을 조회한 뒤 사용자가 선택한 계좌만 보유·주문·매수 가능 금액 조회에 사용해야 한다. 계좌가 하나여도 계좌를 암묵적으로 고르지 않아야 한다. 계좌 식별자는 LLM 입력, 에이전트 상태, 로그와 보고서에 포함하지 않아야 한다.

#### Scenario: 여러 계좌 선택

- **WHEN** 계좌가 여러 개 반환될 때
- **THEN** 사용자가 하나를 선택하기 전 계좌별 API 호출을 하지 않는다

#### Scenario: 계좌 없음

- **WHEN** 계좌 목록이 비어 있을 때
- **THEN** 빈 계좌 결과를 반환하고 임의 계좌나 값을 만들지 않는다

### Requirement: 주문 데이터의 제한과 누락을 표시

시스템 MUST 공식 API의 OPEN/CLOSED 상태 분류, 주문 상세와 페이지 제한을 준수해야 한다. 순회 횟수와 재시도 횟수는 유한해야 하며 API가 반환하지 않는 주문 유형·기간은 완전한 거래 원장으로 취급하지 않아야 한다.

#### Scenario: 부분 체결

- **WHEN** 주문 수량과 체결 수량이 다른 주문을 받으면
- **THEN** 주문 수량과 체결 수량을 별도 필드로 유지한다

#### Scenario: 일부 주문 조회 실패

- **WHEN** 주문 상세 또는 페이지 요청 일부가 실패하면
- **THEN** 조회된 결과는 보존하고 누락 범위와 실패를 보고한다

### Requirement: 비밀과 원시 응답 보호

시스템 MUST client secret과 토큰을 인증 모듈 내부에 보관하고 원시 계좌 응답을 프롬프트·로그·원격 추적에 보내지 않아야 한다. 개인 계좌 데이터는 기본 로컬 저장 영역에만 기록해야 한다.

#### Scenario: 인증 실패 및 호출 제한

- **WHEN** 인증 실패, 만료, 호출 제한 또는 타임아웃이 발생하면
- **THEN** 비밀·계좌 식별자를 노출하지 않고 재시도 가능한 경우에만 제한된 횟수로 재시도한다

#### Scenario: 브로커 읽기 전용 권한 미확인

- **WHEN** 사용자가 브로커 측 읽기 전용 권한을 확인하지 않았으면
- **THEN** 실계좌 호출을 중단하고 미확인 상태를 안내한다

#### Scenario: 시나리오 추적 격리

- **WHEN** 계좌 정보로 외부 LLM 분석을 수행하면
- **THEN** 원격 추적 전송을 비활성화하고 계좌 ID, 계좌번호, 토큰 및 원시 응답을 프롬프트에서 제외한다
