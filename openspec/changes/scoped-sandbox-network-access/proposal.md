# 프로젝트 한정 샌드박스 네트워크 정책

## Why
스킬이 사용하는 목적지를 빠짐없이 내보내고, 설정 파일 존재와 실제 샌드박스 정책 적용을 구분해야 한다.

## What Changes
- 공개 공시·시장 보고서·발굴·Yahoo 인증 보조 목적지를 정책에 포함한다.
- 기존 JSON/text를 유지하고 검토용 codex-toml 출력을 추가한다. 미확인 목적지가 있으면 생성을 거부한다.
- 프로젝트 설정·연결·명시적 차단 확인을 분리하고 훅의 성공을 샌드박스 적용으로 해석하지 않는다.
- 정확한 호스트만 허용하며 사설망 포괄 허용과 상위 프록시를 끈다. 활성 배포는 관리형 정책과 일반 실행 경로 검증을 통과해야 한다.

## Trial Validation
- 실행 환경 확인 → 공개 목적지 조사 → 프로젝트 시험 적용 → 독립 Codex·Orca 기본 새 세션 순서로 검증한다.
- 호스트 DNS·HEAD는 허용 목록 근거이며 샌드박스 성공 증거가 아니다. 중첩 `codex sandbox`를 최종 검증에 사용하지 않는다.
- 직접 연결은 확인한 공개 IP와 원래 호스트명으로 검사한다. 정책 무시·우회 시 시험 변경만 되돌린다.
- 실제 충돌이 확인된 경우에만 관리자 변경을 제시한다. 미검증 항목은 그대로 남긴다. 새 워크트리 검증은 커밋 요청 후 진행한다.

## Out of Scope
전역 설정 변경, 승인 조건 완화, 실계좌·유료 LLM 개발 검증, 커밋·푸시·병합은 포함하지 않는다.
