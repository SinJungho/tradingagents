# Design

## 결정

1. `trade_date`를 기준으로 날짜 누락을 보완한다. 모델이 미래 날짜를 보내도 기존 `as_of` 규칙으로 실행 기준일을 넘지 않는다. Toss 거래 조회의 기본 날짜와 상한 검증은 API 기준 시간대인 KST 달력을 사용하고, 종료일만 지정한 요청은 해당 날짜에 끝나는 30일 창으로 보완한다.
2. 종목 뉴스는 기본 7일 창을 쓰고, 지표·거시 데이터·예측시장 검색에는 문서화된 기본값을 쓴다. 사용자가 명시한 값은 기존 검증·날짜 제한을 유지한다.
3. 시장 지표 도구의 기본 지표 묶음은 기존에 지원되는 추세·모멘텀·변동성 지표만 포함한다.
4. 종목당 분석 라운드를 3회 허용해 가격 이력, 지표, 검증 스냅샷을 수집할 수 있게 한다. 전체 재귀 제한은 함께 올려 분석이 중간 종료되지 않도록 한다.
5. ETF·뮤추얼펀드는 Yahoo의 `funds_data`를 사용하고, 관측 시각이 제공되지 않는 값은 그 사실을 함께 기록한다.
6. Toss 현재 USD/KRW 환율은 매매기준율을 기준으로 사용하고, API가 제공하는 유효 종료 시각이 지난 환율은 통합 합계에 적용하지 않는다. 참고 환율은 실제 체결 환율과 다를 수 있음을 표시한다.
7. Toss 거래내역은 계좌 API로 읽기 전용 조회하고 거래 유형·자산군·결제 상태별 건수만 보고한다. 시작일만 적용하고 종료일을 생략해 미결제 거래를 포함한다. 거래 금액은 취소 레코드에서 방향이 보장되지 않으므로 기간 손익이나 잔액으로 합산하지 않는다.
8. Toss 보유 조회는 KR/미국 주식만 포함한다. 옵션·채권 거래가 조회되어도 현재 보유수량·평가액을 거래내역으로 재구성하지 않는다.

## 검증

- 모델이 날짜와 일부 검색 인자를 생략해도 합성 공급자 호출이 실행 기준일과 기본 인자를 받는지 테스트한다.
- 명시된 과거 날짜와 창은 유지되고 미래 입력은 실행 기준일로 제한되는지 확인한다.
- 포트폴리오 분석 기본 설정이 세 차례 도구 라운드를 허용하는지 확인한다.
- 기존 금융 데이터 보안·민감정보 제외 규칙을 유지한다.
- 합성 Toss 응답으로 FX 유효시각, 거래내역 페이지 경계, 자산군 요약과 보고서 민감정보 제외를 확인한다.
