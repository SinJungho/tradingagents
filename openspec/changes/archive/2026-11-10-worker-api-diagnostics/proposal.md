# Proposal

## Why

Orca 워커와 하위 에이전트는 별도 프로세스 또는 실행 호스트에서 시작될 수 있어 부모 세션의 환경변수와 로컬 인증 파일을 자동으로 사용할 수 있다고 가정할 수 없다. 현재 포트폴리오 조회와 시나리오 분석은 대부분의 예외를 일반 실패로 바꾸므로, 실행 환경·인증 설정·네트워크 문제와 공급자 응답을 구분하기 어렵다.

## What Changes

- `tradingagents doctor` 명령으로 현재 프로세스의 작업 디렉터리, 확인 가능한 Orca 실행 환경, 선택된 LLM 제공자와 인증 방식, 관련 환경변수의 설정 여부, 주요 API 호스트의 HTTP(S) 도달성을 진단한다.
- 진단과 오류 보고에는 변수명과 설정 여부, 오류 분류, HTTP 상태, 재시도 가능 여부만 포함한다. 자격 증명 값, 계좌 식별자와 원시 응답은 표시하지 않는다.
- 토스 조회와 포트폴리오 시나리오 실패를 DNS, 연결, 타임아웃, 인증, 권한, 호출 한도, 공급자 서버, 응답 형식 오류로 구분한다. 이미 있는 제한 재시도를 유지하고 인증 거부와 할당량 초과는 반복하지 않는다.
- 워커별 인증은 워커가 실행되는 호스트의 환경변수 또는 기존 로컬 ChatGPT 인증 파일에 맡긴다. 프롬프트·작업 메시지로 비밀을 복사하는 기능은 추가하지 않는다.

## Capabilities

### New Capabilities

- `worker-api-diagnostics`: 현재 실행 프로세스의 API 설정과 도달성을 비밀 노출 없이 점검한다.

### Modified Capabilities

- `toss-account-read`: 안전한 API 실패 분류와 제한된 재시도 상태를 제공한다.
- `portfolio-scenario-analysis`: 심볼 조사와 시나리오 분석의 실패 원인을 분류해 부분 결과에 표시한다.

## Out of Scope

- Orca의 비밀 저장소에 자격 증명을 생성하거나 다른 호스트로 복사하는 작업
- 브로커 쓰기, 실계좌 진단 요청, 실제 LLM 호출
- 현재 프로세스에서 읽을 수 없는 원격 호스트의 파일이나 환경변수 추측

## Impact

- CLI 진단 명령, 포트폴리오 오류 분류와 리포트 스키마, 문서와 합성 테스트
- 새 런타임 의존성 없음
