# Design

## Context

TradingAgents는 LLM 제공자를 환경변수로 인증하고, Toss 계좌 API는 `TOSS_CLIENT_ID`와 `TOSS_CLIENT_SECRET`을 사용한다. ChatGPT plan 인증은 사용자 홈의 기존 로컬 인증 파일을 사용한다. Orca 워커는 별도 실행 호스트일 수 있으므로 진단은 현재 프로세스에서 관측 가능한 상태만 표시해야 한다.

## Decisions

1. **현재 프로세스 기준 진단**: `doctor`는 프로세스의 작업 디렉터리, `ORCA_ENVIRONMENT`가 있으면 제한된 식별값, 없으면 미노출 상태를 표시한다. 부모 세션이나 원격 호스트 상태를 추정하지 않는다.
2. **비밀 비노출**: 활성 quick/deep LLM 제공자의 필요한 변수와 Toss·Alpha Vantage·FRED·SEC 설정 변수를 이름 및 설정 여부로만 출력한다. ChatGPT 인증은 기존 상태 조회 함수를 호출해 연결 여부만 표시한다. endpoint URL, 환경변수 값, 인증 파일 내용은 출력하지 않는다.
3. **비인증 도달성 검사**: 선택된 LLM endpoint와 데이터 제공자 호스트에 인증 헤더·쿼리·본문을 붙이지 않고 리다이렉트를 따르지 않는 HTTP(S) `HEAD`를 보낸다. HTTP 응답을 받으면 도달 가능으로 처리하며 본문은 읽거나 표시하지 않는다. 사용자 지정 로컬 endpoint의 HTTP 연결도 확인한다.
4. **분류된 실패**: 공유 분류기는 예외 클래스와 HTTP 상태만 사용해 오류 범주와 retryable 플래그를 산출한다. 응답 본문·예외 문자열은 분류나 출력에 사용하지 않는다.
5. **재시도**: Toss의 기존 연결·타임아웃·서버 오류 재시도를 유지하고 토큰 발급 경로에도 동일한 유한 재시도를 적용한다. 인증·권한·할당량 오류는 재호출하지 않는다. LLM SDK가 수행한 재시도 횟수는 오류 출력에 추측해 쓰지 않는다.
6. **보고서 계약**: 실패한 심볼 조사에는 분류명과 재시도 가능 여부만 추가한다. 포트폴리오의 데이터 원천 실패에도 같은 안전한 설명을 기록한다.

## Verification

- 테스트에서는 합성 환경변수와 모의 HTTP(S) 응답만 사용한다.
- 출력에 자격 증명 값, Toss 계좌 식별자 또는 응답 본문이 없는지 검증한다.
- 네트워크, 인증, 권한, 호출 제한, 서버 오류와 설정 누락을 구분하고 호출 재시도 횟수가 제한되는지 확인한다.
