## ADDED Requirements

### Requirement: 사용자 차트 역할과 범위의 증거

에이전트 MUST 실제 Yahoo Finance 대상 탭을 확인한 뒤 승인된 표시만 변경하고, 역할별 색상·선 종류·라벨과 요청된 화면 범위를 재열기 후 확인해야 한다. 검증 CLI MUST 이전 형식을 지원하고 새 증거에서 교체 전·후 객체, 스타일, 확인한 일봉 범위를 검사해야 한다.

#### Scenario: 기존 추세선의 연장 또는 색 수정

- **WHEN** 기존 추세선의 좌표나 스타일을 교체할 때
- **THEN** 사전 조회는 기존 객체가 한 벌, 변경 직후와 재열기 조회는 새 객체가 한 벌이고 옛 객체가 없는지를 검사한다
- **AND** 색상·패턴과 라벨 문자열이 요청한 값으로 유지됐는지 확인한다

#### Scenario: 역할별 색상 적용

- **WHEN** 각 역할에 다른 색상을 요청받을 때
- **THEN** 초록색 장기 하단과 같이 확인한 기존 역할을 유지하고 역할마다 구분되는 색을 기록한다
- **AND** 수평선과 연결된 라벨은 같은 역할과 가격으로 표시하고 실제 화면에서 함께 읽히는지 확인한다

#### Scenario: 한 화면의 최소 일봉 수와 탭 복귀

- **WHEN** 사용자가 특정 봉 수를 한 화면에서 확인하거나 원래 탭에 복귀하기를 요청할 때
- **THEN** 전체 로드 봉 수와 한 화면에 확인한 거래일 범위의 봉 수를 별도로 기록하고 부족하면 해당 단계만 미완료로 보고한다
- **AND** 실제 차트 캡처를 남기고 승인된 경우 원래 선택 탭으로 복귀한다

### Requirement: 차트와 투자 시나리오 Markdown 결과

에이전트 MUST 작업 결과 보고서 파일의 형식 개선 요청을 파일에 반영해야 한다. 요약과 기준 시각, 시나리오, 색상 범례·가격 및 근거, 완료 검증과 미확인은 읽기 쉽게 구분해야 한다.

#### Scenario: 저장된 보고서의 가독성 수정

- **WHEN** 사용자가 Markdown 보고서 파일의 가독성을 개선해 달라고 요청할 때
- **THEN** 기존 파일의 판단과 기준 시각을 앞에 두고, 짧은 문단·기간별 목록·비교 표를 사용하며 최종 화면과 계산 근거를 연결한다
