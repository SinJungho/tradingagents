# portfolio-scenario-analysis Specification

## Purpose

한국·미국 보유 현황과 조회 가능한 주문 사실을 정확히 요약하고, 기존 시장 분석을 바탕으로 포트폴리오에 영향을 주는 기간별 시나리오를 제공한다.

## ADDED Requirements

### Requirement: 정규화된 금융 데이터 계산

시스템 MUST 시장, 거래소, 종목 코드, 통화, 기준 시각과 출처를 보존해야 한다. 종목 매핑은 명시적이어야 하며 실패하면 미지원으로 표시해야 한다. 금액은 Decimal 정밀도로 계산하고 KRW와 USD는 서로 환산한 근거와 환율 기준 시각이 있을 때만 합산해야 한다.

#### Scenario: 환율 누락

- **WHEN** KRW/USD 통합 비중이 필요하지만 유효한 환율이 없을 때
- **THEN** 통화별 금액과 비중만 제공하고 통합 합계를 만들지 않는다

#### Scenario: 매핑 미지원

- **WHEN** 토스 종목 코드를 기존 데이터 공급자 심볼로 명확히 매핑하지 못할 때
- **THEN** 해당 종목을 미지원으로 표시하고 다른 종목으로 대체하지 않는다

#### Scenario: 손익 자료 부족

- **WHEN** 매입원가, 실현 내역 또는 환차손익 계산 자료가 충분하지 않을 때
- **THEN** 수치 대신 미확인으로 표시하고 이를 추정하지 않는다

### Requirement: 계좌 전체 포트폴리오 요약

시스템 MUST 보유 비중, 현금성 비중, 평가손익, 종목·시장·통화 집중도를 코드로 계산해야 한다. 매수 가능 금액은 실제 현금 잔고와 구분해야 한다. 업종·상관관계는 자료가 있을 때만 분석해야 한다.

#### Scenario: 빈 포트폴리오

- **WHEN** 보유 종목과 매수 가능 금액이 모두 비어 있거나 0일 때
- **THEN** 빈 포트폴리오를 사실대로 표시하고 0을 임의로 채우지 않는다

#### Scenario: 주문 이력 요약

- **WHEN** 주문 목록·상세가 반환될 때
- **THEN** 주문·체결 수량, 상태, 거래 빈도 등 관측 가능한 사실만 요약하고 투자자의 의도나 심리를 추정하지 않는다

### Requirement: 기간별 시나리오

시스템 MUST 설정 가능한 단기(기본 1~20거래일), 중기(기본 1~6개월), 장기(기본 6~24개월)에 대해 상승·기본·하락 시나리오를 제공해야 한다. 각 시나리오는 논리, 근거와 출처 시각, 촉매, 관찰 조건, 검토 조건, 무효화 조건, 위험과 현재 포트폴리오 영향을 포함해야 한다. 계산·보정 방식이 없는 확률·예상 수익률·목표 가격을 제시해서는 안 된다.

#### Scenario: 근거가 부족한 기간

- **WHEN** 특정 기간의 자료나 종목 분석이 누락되었을 때
- **THEN** 성공한 다른 분석은 보존하고 누락 자료·기간·한계를 표시하며 근거 없는 시나리오 내용을 생성하지 않는다

#### Scenario: 제안 전용 언어

- **WHEN** 매매 관련 표현을 출력할 때
- **THEN** 분석 제안으로 표현하고 주문 생성·실행 지시 기능을 제공하지 않는다

### Requirement: 격리된 분석 실행

시스템 MUST 포트폴리오 상태를 기존 종목별 메모리와 체크포인트에 저장하지 않아야 한다. 관심종목은 사용자가 지정한 범위에서만 분석하고 동일 실행 안의 수집은 재사용해야 한다. 외부 뉴스와 문서는 신뢰할 수 없는 데이터로만 취급해야 한다.

#### Scenario: 합성 데이터 데모

- **WHEN** 데모 모드로 실행할 때
- **THEN** 인증정보·실제 계좌·실제 LLM 요청 없이 합성 데이터로 JSON과 한국어 Markdown을 생성한다

#### Scenario: JSON 계약 검증

- **WHEN** JSON 결과를 생성할 때
- **THEN** 명시된 결과 스키마를 검증하고 검증 여부를 사실 정확성이나 투자 성과 검증으로 설명하지 않는다
