## MODIFIED Requirements

### Requirement: 분류된 API 실패와 제한된 재시도

시스템 MUST Toss API 실패를 분류하고 응답 본문, 자격 증명 및 계좌 식별자를 오류에 포함하지 않아야 한다. 현재가 GET이 HTTP 401을 반환하면 기존 토큰을 무효화하고 새 토큰으로 한 번 재시도해야 한다. 재시도도 401이면 인증 실패로 반환하고 추가 요청을 보내지 않아야 한다. 다른 경로의 인증 오류와 권한·할당량 오류는 반복하지 않아야 한다.

#### Scenario: 현재가 조회 중 이전 토큰 거부

- **WHEN** Toss 읽기 전용 GET이 첫 요청에서 401을 반환하고 새 토큰 요청이 성공할 때
- **THEN** 캐시된 토큰을 폐기하고 같은 GET을 새 토큰으로 한 번 재시도한다

#### Scenario: 현재가 토큰 갱신 후에도 인증 거부

- **WHEN** 새 토큰을 사용한 재시도도 401을 반환할 때
- **THEN** 안전한 인증 오류를 반환하고 GET 재시도를 종료한다
- **AND** 응답 본문, 토큰, 계좌 식별자를 노출하지 않는다

#### Scenario: 네트워크 오류

- **WHEN** Toss API DNS, 연결 또는 timeout 실패가 재시도 한도까지 반복될 때
- **THEN** 어댑터는 오류 분류와 retryable 상태를 제공하고 요청 횟수는 설정된 유한 상한을 넘지 않는다

#### Scenario: 인증·권한·호출 제한

- **WHEN** Toss API가 인증, 권한 또는 할당량 오류를 반환할 때
- **THEN** 오류에는 상태 분류만 남기고 응답 본문이나 계좌 정보를 출력하지 않으며, 현재가 경로의 1회 갱신 재시도 후에는 반복하지 않는다

#### Scenario: 권한 또는 호출 한도 거부

- **WHEN** GET이 403 또는 429를 반환할 때
- **THEN** 토큰 갱신이나 반복 GET 없이 분류된 오류를 반환한다
