# toss-account-read Specification Delta

## ADDED Requirements

### Requirement: 보유 분석 필드와 시각 보존

시스템 MUST Toss 보유 응답의 계좌 요약과 종목별 매수 평균가, 수량, 가격, 평가액, 손익률, 일간 손익, 수수료 및 세금을 Decimal 값으로 정규화해야 한다. 누락된 응답 필드는 알 수 없음으로 유지해야 한다. HTTP 조회 시각을 금융 자료의 기준 시각으로 가장하지 않아야 한다.

#### Scenario: 보유 손익 필드가 반환됨

- **WHEN** Toss가 종목별 일간 손익·손익률 또는 비용 필드를 반환할 때
- **THEN** 시스템은 해당 필드를 보유 모델과 결정론적 분석 보고서에 보존한다

#### Scenario: 보유 자료 기준 시각 없음

- **WHEN** 보유 응답에 금융 자료 기준 시각이 없을 때
- **THEN** 보고서는 조회 시각과 자료 기준 시각을 별도로 표시하고 자료 기준 시각은 미확인으로 둔다

### Requirement: 시장 가격과 캔들의 조회 전용 연결

시스템 MUST Toss 공식 호스트의 승인된 현재가·일봉 캔들 경로에 대해서만 조회 `GET`을 전송해야 한다. 가격·캔들 응답은 심볼, 통화, 거래 기준 시각, 조회 시각과 OHLCV를 검증해 보존해야 한다. 캔들 조회는 공식 페이지 한도를 지켜야 한다.

#### Scenario: 가격·캔들 정상 응답

- **WHEN** 현재가 또는 일봉 캔들 응답이 반환될 때
- **THEN** 시스템은 검증된 시장 데이터만 정규화해 기술 분석에 전달한다

#### Scenario: 가격·캔들 오류 또는 기준 시각 누락

- **WHEN** 응답이 잘못되었거나 자료 기준 시각이 없을 때
- **THEN** 시스템은 해당 자료를 미확인으로 표시하고 계좌 정보나 응답 본문을 오류에 포함하지 않는다

### Requirement: 거래 상세의 메모리 격리

시스템 MAY 거래별 가격·수량·금액·비용·환율·시각을 메모리에서 정규화해 손익 계산에 사용할 수 있다. 거래 상세 행과 식별자는 프롬프트·로그·보고서·원격 추적에 포함해서는 안 된다. 완전한 거래 범위와 원가가 검증되지 않거나 재구성한 잔량이 현재 보유 수량과 일치하지 않으면 실현손익을 계산하지 않고 미확인으로 표시해야 한다.

#### Scenario: 완전한 주식 거래 원장

- **WHEN** 반환 거래가 완전하고 매수·매도 원가를 일관되게 계산할 수 있으며 거래 원장 잔량이 현재 보유 수량과 일치할 때
- **THEN** 시스템은 통화별 가중평균원가 방식의 분석용 실현손익만 집계해 보고한다

#### Scenario: 원장 누락 또는 원가 불명

- **WHEN** 페이지가 더 있거나, 이체·취소·누락 가격·수량 등으로 원가를 확정할 수 없을 때
- **THEN** 해당 통화의 실현손익은 미확인으로 표시하고 거래별 금액은 노출하지 않는다
